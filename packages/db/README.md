## Urutan auth

BSD memasang FK nyata dari tabel domain dan trigger `user_admission` ke `auth."user"`, padahal tabel itu milik Better Auth. Dipilih: **`auth."user"` dibuat di `0002` dengan kolom inti Better Auth** (bentuk stub `bsd-check`, id `uuid`), bukan menunda FK. Alasannya FK dan trigger aktif dan teruji sejak S4 tanpa jendela tanpa pagar.

Akibatnya untuk migrasi Better Auth (S4 sisi server, diterapkan di `0009`, ADR 0007):

- File hasil generator **tidak boleh** `create table "user"`. Kolom plugin ditambah lewat `alter table auth."user" add column ...` (mis. `"twoFactorEnabled"`).
- Tabel `session`, `account`, `verification`, `passkey`, `twoFactor` dibuat di skema `auth` dengan id dan FK `uuid` ke `auth."user" (id) on delete cascade` (dibutuhkan `jobs.purge_unfinished_users`). Hak `dompetku_web` ikut otomatis lewat default privileges dari `0003`.

## Yang perlu diketahui sebelum diterapkan di VM

- Deployer (`infra/db-vm/deploy/deploy`) menjalankan `dbmate up` dari migrasi di image rilis. Migrasi ini ikut rilis berikutnya setelah merge ke `main`.
- Runbook VM: pastikan `app.settings.env = 'prod'` (bawaan 0001; jangan diubah) dan isi `app.settings.owner_email` dari `AUTH_OWNER_EMAIL` (dibandingkan tanpa beda huruf besar/spasi). Tanpa `owner_email` tidak ada yang bisa mendaftar (`signup_closed`). Selama `env = 'prod'`, blok `migrate:down` 0002 sampai 0008 menolak berjalan (`migrate_down_blocked_prod`); CI dan lokal mengubah `env` ke `dev` sebelum rollback.
- Email `auth."user"` tidak bisa diganti (`email_immutable`): fitur `changeEmail` Better Auth tetap mati.
- `audit.log` menolak event sistem (`audit_event_reserved`). `db_manual_access` ditulis langsung sebagai owner (`insert into audit.events`) oleh skrip host `infra/db-vm/bin/dompetku-psql` sebelum sesi dibuka (`docs/ops/akses-db-manual.md`); `deploy` dicadangkan untuk deployer (saat ini deployer hanya menulis `deploy.log`). Tes katalog mendeteksi event yang ditulis langsung oleh fungsi DEFINER/owner (atau lewat `private.purge_entries`) dan gagal bila event itu tidak ada di daftar reserved `audit.log`.
- pgaudit: `dompetku_auditlog` sudah punya hak di semua tabel `app`, `audit`, `auth` dan default privileges untuk tabel baru, jadi tabel Better Auth ikut teraudit.
- Fungsi undangan pra-login (`invitation_peek`, `decline_invitation`) dan `accept_invitation` mengisi GUC `app.invite_token_hash` dengan `set_config(..., true)`: nilainya bertahan sampai akhir transaksi, bukan hanya di dalam fungsi. Panggil di transaksi sendiri, jangan digabung dengan operasi lain dalam satu `withUser`.
- **Membetulkan email yang salah ketik** (`email_immutable` menolak dari aplikasi). Undangan yang salah alamat cukup dicabut/dikirim ulang (`api.resend_invitation`); prosedur ini hanya untuk akun yang sudah jadi. Lewat `dompetku-psql` sebagai `dompetku_owner` (bawaan; pemilik tabel `auth."user"`, jadi boleh `disable trigger`). Alat itu sudah menulis `db_manual_access` dan mengirim alert sebelum sesi dibuka; baris `insert` di bawah menambah event kedua yang mengikat user yang disentuh. Satu transaksi lewat stdin (email tidak terlihat di daftar proses):

  ```bash
  sudo /opt/dompetku/bin/dompetku-psql -- "email_fix" <<'SQL'
  \set email '<email lama>'
  \set email_baru '<email baru>'
  begin;
  select id as uid from auth."user" where email = lower(btrim(:'email')) \gset
  insert into audit.events (event, user_id, meta)
    values ('db_manual_access', :'uid', '{"via": "cli", "reason": "email_fix"}');
  alter table auth."user" disable trigger user_email_immutable;
  update auth."user" set email = lower(btrim(:'email_baru')), "emailVerified" = false, "updatedAt" = now()
   where id = :'uid';
  alter table auth."user" enable trigger user_email_immutable;
  delete from auth.session where "userId" = :'uid';  -- paksa masuk ulang
  commit;
  SQL
  ```

  Lalu minta pemilik akun memverifikasi email baru lewat alur lupa kata sandi. Bila email itu akun pemilik, samakan `app.settings.owner_email`. Trigger dimatikan hanya di dalam transaksi itu; `disable trigger` butuh pemilik tabel atau superuser.

- **Sesudah mengubah `households.payday_rule` atau mengisi `app.holidays`** (libur tahunan, cuti bersama baru): aturan satu kewajiban hanya dinilai saat tulis, jadi label periode kemunculan tagihan bisa bergeser tanpa penolakan. DQ13 di `jobs.dq_reconcile` (01:00 WIB berikutnya, alert `dompetku-dq`) menangkapnya untuk label periode berjalan ke depan (label lampau tidak dinilai lagi); perbaiki dengan menghapus atau melepas `wajib` anggaran yang bentrok, atau mengarsipkan tagihannya.
- Pembanding email di trigger memakai `lower(btrim(email))`, tetapi `unique` di `auth."user".email` peka huruf besar. Better Auth harus menormalkan email ke huruf kecil sebelum insert.
- Role `dompetku_test`, skema `tap`/`tests`, dan ekstensi pgTAP hanya ada di cluster CI/lokal (`tests/support/setup.sql`), tidak pernah di VM.

## Tes pgTAP

`tests/support/setup.sql` (superuser, sekali setelah `dbmate up`) memasang pgTAP di skema `tap`, role `dompetku_test` (login, bukan superuser, tanpa keanggotaan role aplikasi), dan helper `tests.<role>_exec/_val(uid, sql)`: fungsi `SECURITY DEFINER` milik `dompetku_web`, `dompetku_api`, `dompetku_worker`, `dompetku_owner`. Setiap aksi tes berjalan sebagai role aplikasi itu dengan `app.user_id` = `uid`, sehingga RLS, grant, dan trigger diuji seperti di produksi. Jam dimajukan dengan `tests.clock(interval)` (env `test`, di dalam transaksi tes).

## Tes integrasi auth

`apps/web` punya tes Vitest terhadap Postgres sungguhan (`src/server/auth/__int__/`) dan e2e Playwright mode nyata (`tests/e2e-auth/`). Lokal, setelah `dbmate up` di cluster sekali pakai:

```bash
TEST_DATABASE_URL='postgres://dompetku_web@127.0.0.1:5432/dompetku' \
TEST_DATABASE_ADMIN_URL='postgres://postgres@127.0.0.1:5432/dompetku' \
  pnpm --filter @dompetku/web test:int
```

Tes mengosongkan data (sebagai superuser) dan memasang `owner_email` sendiri; jangan arahkan ke DB yang dipakai. Langkah operasi: `docs/ops/auth.md`.

## E2E mode nyata (auth dan ledger)

`e2e:auth` (alur auth) dan `e2e:ledger` (kriteria keluar S6: Catat ≤ 3 ketukan, Batalkan/Sampah/Pulihkan, idempotensi, konflik versi, kanari Bersama, axe, budget JS mode nyata) menjalankan build standalone tanpa `NEXT_PUBLIC_PROTOTYPE` terhadap cluster sekali pakai yang sama (port 3300 dan 3301). Global setup mengosongkan data dan memasang `owner_email`; pemilik didaftarkan lewat alur nyata dengan passkey virtual. Lokal, setelah `dbmate up`:

```bash
pnpm build
export AUTH_E2E_DATABASE_URL='postgres://dompetku_web@127.0.0.1:5432/dompetku'
export AUTH_E2E_ADMIN_URL='postgres://postgres@127.0.0.1:5432/dompetku'
PW_CHROMIUM_PATH=/opt/pw-browsers/chromium pnpm --filter @dompetku/web e2e:auth
PW_CHROMIUM_PATH=/opt/pw-browsers/chromium pnpm --filter @dompetku/web e2e:ledger
```

Setiap suite membutuhkan DB bersih: jalankan `bash docs/superpowers/handoff/db-reset-lokal.sh` sebelum `e2e:ledger` bila `e2e:auth` baru berjalan. Jalankan berurutan (keduanya menyalin `.next/static` ke folder standalone yang sama dan mengosongkan data). CI menjalankan keduanya di job `auth`.
