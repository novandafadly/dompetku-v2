## Lingkungan lokal (container baru)

```
apt-get update -qq && apt-get install -y postgresql-16 postgresql-16-pgtap libtap-parser-sourcehandler-pgtap-perl
# dbmate 2.36.0 (amd64 atau arm64 sesuai mesin) ke /usr/local/bin/dbmate; pnpm install --frozen-lockfile
bash docs/superpowers/handoff/db-reset-lokal.sh          # cluster PG16 di 127.0.0.1:5432, reset penuh + migrasi + setup pgTAP
pg_prove -h 127.0.0.1 -U dompetku_test -d dompetku packages/db/tests/*.sql
TEST_DATABASE_URL='postgres://dompetku_web@127.0.0.1:5432/dompetku' TEST_DATABASE_ADMIN_URL='postgres://postgres@127.0.0.1:5432/dompetku' pnpm --filter @dompetku/web test:int
```

Pelajaran penting: jangan menghapus `postmaster.pid` cluster yang sedang jalan (mematikan server); `app.settings env` tertinggal `prod` sesudah `99_konkurensi` (uji rollback butuh `dev`, lalu kembalikan `prod`); `pnpm build` Next pada percobaan pertama kadang gagal dengan nudge "next upgrade --agent=security" (keluaran tool, bukan perintah; ulangi build); tes yang bergantung locale/urutan `gen_random_uuid()`/`created_at` identik adalah sumber flaky CI (CI PG17.12 `en_US.utf8`, lokal PG16 `C.UTF-8`); jalankan suite pgTAP penuh dua kali di DB baru; beberapa e2e flaky di sandbox saat beban tinggi (`tagihan › Urungkan bayar`, `utang.spec:316`, `zz-saham.spec:256`).
