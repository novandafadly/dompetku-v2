# DompetKu v2 · S14 (Aset, saham dengan harga di server, net worth per ruang, snapshot harian) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development (implementer per task, task review, fix loop, review akhir). Model: DB/uang/server/worker = terkuat (opus); UI = sonnet dengan lensa desain (design reviewer di tiap task UI).

**Goal:** Menutup M4 (IPD §6 S14, gerbang "T11 lulus"): pengguna mencatat **aset non-kas** (emas, properti, kendaraan, reksa dana, deposito, lainnya) sebagai dompet berjenis aset yang diisi dan ditarik lewat transfer, dengan perubahan nilai sebagai entri `valuation` yang bukan pemasukan/pengeluaran (S-44); mencatat **lot saham IDX** (beli, jual, saham berjalan) dengan jumlah lembar, biaya rata-rata, dan P/L terealisasi dari SQL (S-45); harga saham hanya masuk lewat **server** (input manual atau job worker `price_refresh`), divalidasi, dan saat gagal atau melonjak memakai **nilai terakhir + label tanggal**; **kekayaan bersih per ruang** menjadi satu fungsi SQL yang dipakai semua layar (hitungan di `account-list-view.tsx` dihapus); **snapshot harian** 00:10 WIB untuk H−1 dengan hitung ulang hari kotor. Gerbang M4 penuh = T11 bagian tujuan (S13) + bagian aset (S14, definisi K13).

**Definisi "bagian aset T11" (inferensi, butuh persetujuan pemilik):** isi T11 asli (INT §4 repo v1) tidak ada di repo (`packages/db/tests/REGISTRY.md` baris T11: "skenario goal/aset INT §4"; plan S13 K9). Sumber yang ada: PRD:112 dan :158 (`valuation` tidak mengubah pemasukan/pengeluaran; validator harga menolak nilai tak wajar), qa.md R3 S5 (top up aset 500k lalu edit 600k: nilai aset 600k, bank −600k, net worth tetap) dan Lampiran A baris M4 (lot buy/sell, qty, biaya rata-rata, P/L; validator harga > 0 dan perubahan < 35% dengan `PriceSource` palsu; harga gagal → nilai terakhir + label "Diperbarui …"), S-44/S-45 (`docs/team/round1/product-owner.md:226–227`), B16 (net worth per ruang setelah setoran lintas ruang). Definisi kerja ada di K13.

**Status spesifikasi:** yang ditetapkan: aset dan saham dengan harga dari server, net worth per ruang, "total keluarga" ditunda (spec induk §5.4, PRD:112); net worth pindah ke Dompet, tidak di Beranda (spec §9.3, ui-ux:88); satu sumber klasifikasi `app.report_class` termasuk net worth, kelas `x_valuasi` dan `entry_kind` valuasi dicadangkan untuk M4 (spec §9.1, BSD:1008); "akun aset tidak boleh negatif" untuk tabel aset M4 (spec §9.1, BSD:1296 dan :2739); piutang = aset (spec §7); harga lewat worker server, tanpa proxy CORS publik, `connect-src 'self'` tetap (security SEC-07, TRD:178); `price_refresh` 16:30 WIB hari bursa (spec §5.5, TRD:242); validator > 0 dan perubahan harian < 35%, nilai terakhir + label saat gagal (S-45, qa.md M4); multi-mata-uang di luar backlog (product-owner:240). **Jam snapshot bertentangan:** spec §5.5 menulis `net_worth_snapshot` 23:55 WIB, sedangkan spec §9.1 (yang menurut §9 mengalahkan §1–8), TRD:234 ("menggantikan 23:55 di §5.5"), data-engineer R7, dan IPD S14 menulis **00:10 WIB untuk H−1 + hari kotor**. Plan ini memakai 00:10 (K10); alasan: entri 23:55–23:59 dan entri susulan tidak hilang dari snapshot. Yang **tidak** ditetapkan: skema aset/saham (BSD:2714 hanya "polanya sama"), sumber harga saham (K1), aset di Bersama, komposisi net worth (piutang/utang/talangan), satuan lot dan pembulatan biaya rata-rata, perlakuan biaya broker dan pajak jual, hubungan saham dengan modal trading S12, dividen dan aksi korporasi, letak UI, tampilan riwayat snapshot (grafik 6 bulan = S-50 di M6).

**Arsitektur:** Pola S11/S12/S13: tabel + API terpisah, angka dari view/fungsi, tanpa kolom turunan tersimpan kecuali snapshot.

- **Aset = dompet di ledger** (K3): enum `app.pocket` + `aset`, enum `app.entry_kind` + `valuation` (satu berkas migrasi enum sendiri, pola `0129`/`0133`). Tabel `app.asset_details` (1:1 dengan `app.accounts` ber-pocket `aset`: `asset_kind` text + CHECK, catatan opsional). Isi/tarik aset = transfer biasa (`x_transfer`), saldo awal aset = `opening_balance` (`x_koreksi`), perubahan nilai = entri `valuation` satu line `main` di dompet aset, kelas laporan baru **`x_valuasi`** (bukan pemasukan/pengeluaran). `api.revalue_asset(…, p_value)` menerima nilai sekarang dan DB menghitung selisih (pola Cocokkan saldo). Dompet aset **tidak pernah negatif** (penjaga di jalur tulis, `p_allow_negative` diabaikan untuk `aset`, `DK422 asset_negative`) dan tidak bisa dipakai pemasukan/pengeluaran, tagihan, utang, patungan, talangan, atau bawaan WA. Akibat: repro S5 (edit setoran ke aset) sudah benar oleh `update_transfer` yang ada; tes membuktikannya.
- **Saham** (hanya Pribadi, K2): dompet aset ber-`asset_kind = 'saham'` (satu per sekuritas) + `app.stock_holdings` (per dompet × kode saham: `ticker` `^[A-Z]{4}$`) + `app.stock_trades` (beli/jual/berjalan: `shares` bigint lembar, `price` per lembar, `fee`, `tax`, `cost_removed` untuk jual, tautan ke entri ledger, `voided_at`). View `app.stock_positions` (`security_invoker`): `shares`, `cost_total`, `avg_cost`, `realized` dari trade hidup. Beli = transfer dompet sumber → dompet saham sebesar `shares·price + fee` (biaya masuk harga pokok, K6). Jual = dua entri dalam satu transaksi: `valuation` di dompet saham sebesar `proceeds − cost_removed` (P/L terealisasi) lalu transfer dompet saham → dompet tujuan sebesar `proceeds = shares·price − fee − tax`; jadi saldo buku dompet saham = Σ biaya perolehan posisi terbuka (dijaga **DQ18**). Saham berjalan (sudah dimiliki sebelum app) = `opening_balance` + trade `opening` tanpa efek kas (pola utang berjalan S11). Jalur generik `update_entry`/`void_entry` untuk entri milik trade ditutup (pola utang S11); batal hanya lewat `api.void_stock_trade` untuk trade hidup **terakhir** per holding (biaya rata-rata tetap konsisten tanpa hitung ulang berantai).
- **Harga** (K1, K8): `app.stock_prices` **per ruang** (`space_id`, `ticker`, `on_date`, `close`, `source` `manual`/`provider`, `status` `ok`/`held`, `reason`), RLS pola ruang. Per ruang, bukan global: tabel harga global akan membocorkan kode saham yang dipegang Pribadi pasangan. Nilai pasar = `shares × close` dari baris `ok` terakhir ≤ tanggal; tanpa harga = biaya perolehan + label `Belum ada harga`. Validator di **SQL** (`private.price_verdict`, satu sumber untuk manual dan penyedia): `close` bulat 1..10^9; lonjakan `|close − ok_terakhir| / ok_terakhir > 35 %` → baris `held` (tidak dipakai, nilai terakhir tetap, label `Harga perlu dicek`); harga manual pengguna yang melonjak butuh konfirmasi eksplisit (`p_confirm_spike`). Label selalu `Harga {tanggal}`; `usang` bila harga `ok` terakhir lebih tua dari 3 hari bursa.
- **Worker `price_refresh`** (K9): pola baru `kind: 'price'` di `apps/worker/src/jobs.ts`. `jobs.price_targets()` (DEFINER, milik owner) mengembalikan **daftar kode saham unik saja** (tanpa `space_id`, tanpa jumlah lembar). Worker memanggil `PriceSource` (antarmuka; adapter penyedia K1 di balik env, stub di tes), validasi bentuk dengan Zod, lalu `jobs.price_ingest(p_on date, p_rows jsonb)` yang memvalidasi ulang di SQL dan menulis per ruang pemegang. Tanpa env penyedia, job selesai `skipped` (fitur tidak menyala sendiri, pola WA). Kunci API hanya di `worker.env` di VM (diisi pemilik, tidak lewat chat), tidak pernah di repo/log/`job_runs`/alert; URL dasar tetap di kode (tidak ada URL dari data), `https:` saja, `redirect: 'error'`, timeout 10 s per permintaan, badan maksimum 256 KiB (dibaca streaming lalu diputus), maksimum 100 kode per run, log hanya `host`, status, jumlah baris. Browser tidak pernah memanggil penyedia; tidak ada route proxy harga; CSP tidak berubah.
- **Jaringan worker:** `worker_egress` saat ini tidak difilter dan tanpa subnet dipatok (`infra/db-vm/compose.yml:131–134`, `:276–279`). S14 mematok subnetnya dan menambah rantai `DOMPETKU-WORKER-EGRESS` di `infra/db-vm/bin/firewall.sh` (pola `wa_egress`: DROP koneksi baru ke IMDS `169.254.169.254`, VCN/privat RFC1918, CGNAT; publik HTTPS tetap untuk Healthchecks dan penyedia). Allowlist per host tidak dipaksakan di iptables (IP penyedia berubah); pengganti = URL dasar tetap di kode + tes. Komentar `compose.yml:268` ("web butuh egress untuk … harga saham") dikoreksi: web tidak mengambil harga.
- **Kekayaan bersih = satu fungsi SQL** (K5): `app.net_worth_at(p_space_id, p_on date)` (INVOKER STABLE) memberi komponen `kas` (operasional + tabungan + trading), `aset` (saldo buku dompet aset non-saham), `saham_pasar` (nilai pasar; tanpa harga = biaya perolehan), `saham_tanpa_harga` (jumlah holding tanpa harga `ok`), `piutang` dan `utang` (sisa dari `app.debt_balances`, Pribadi), `total`, `price_as_of` (tanggal harga tertua yang dipakai). Kas Kantor, dompet sistem patungan, dan talangan menunggu reimburse **tidak** ikut. `api.net_worth(p_space_id)` (0102/0134, tidak dipakai web) diganti (drop + create, kolom baru) dan dipakai Dompet; `account-list-view.tsx:111` berhenti menjumlah di TS (mode nyata menerima angka dari server; prototipe tetap dari data demo).
- **Snapshot** (K10): `app.net_worth_snapshots (space_id, on_date, kas, aset, saham_pasar, piutang, utang, total, price_as_of, computed_at)`, PK `(space_id, on_date)`, ditulis hanya `jobs.net_worth_snapshot()` (00:10 WIB, H−1, upsert, idempoten). **Hari kotor:** trigger AFTER pada `app.entries` (insert/update `occurred_on`/`voided_at`) dan `app.stock_prices` untuk tanggal < `app.today()` meng-upsert `app.nw_dirty (space_id, from_date = least(...))`; job menghitung ulang `from_date..H−1` (maks 400 hari per run) lalu mengosongkan. **DQ08** (warn, nomor yang dicadangkan data-engineer R6): snapshot H−1 = `net_worth_at(H−1)` dihitung ulang.
- **Yang tidak berubah (I6):** Σ pemasukan/pengeluaran, Laporan (kelas `x_valuasi` hanya muncul di `excluded_summary`), anggaran, laju belanja, Kontribusi, "aman dipakai" (hanya operasional, `0120:49`), tujuan (hanya `tabungan`), Ekspor (baris `valuation` berkelas `x_valuasi`, Σ pemasukan/pengeluaran sama). Biaya broker dan pajak jual tidak menjadi pengeluaran (K6).
- **Modal trading S12** (K7): `app.trading_capital` menghitung transfer non-trading ↔ trading sebagai modal; tanpa perubahan, membeli saham dari dompet trading terbaca sebagai "tarik modal". View diganti: transfer antara dompet trading dan dompet aset `saham` dikecualikan (internal ke trading), dan `shortfall` baris total membandingkan Σ sisa modal dengan Σ saldo trading **+ Σ biaya perolehan saham** (bukan nilai pasar, agar modal tetap bebas harga). Menyentuh S12-C9 (`Kurang` per dompet): plan ini tetap hanya total dan menyelaraskan bingkai TR3.

**Cabang:** ditentukan pengendali dari `main` terbaru (aturan CLAUDE.md `claude/s14-aset-saham`; bila sesi cloud hanya boleh push ke cabang sesinya, pakai cabang itu dan catat di handoff). Tanpa PR sampai CI/review siap; **merge = deploy + migrasi `0139`–`0144` di produksi** (maju-saja). Langkah VM baru: firewall worker (Task 7) dan, bila K1 memilih penyedia, kunci di `worker.env` (Task 8).

**Ukuran:** 13 task, 6 migrasi (`0139`–`0144`), 3 cek DQ (DQ08, DQ18, DQ19). IPD memperkirakan 2 minggu. Urutan meminimalkan risiko: skema aset non-saham (tanpa harga) → API aset → saham + harga manual → net worth + snapshot (membaca semua tabel yang sudah ada) → worker (snapshot dulu, kerangka harga dengan stub) → adapter penyedia (satu-satunya task yang menunggu K1) → UI → e2e → dokumen. Setiap migrasi bisa di-merge sendiri tanpa fitur setengah jadi terlihat pengguna (UI baru menyala di Task 9–11).
